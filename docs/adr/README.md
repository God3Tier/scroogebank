# Architecture Decision Record Index

Use this index to identify which ADRs are relevant before loading their full
text. A one-line summary is a routing aid, not a replacement for an applicable
ADR; humans and agents must read the complete record before making or reviewing
a decision it governs.

## Accepted decisions

- [ADR-0001](ADR-0001-user-directed-push-policy.md) — PRs are the default, while warned and explicitly authorized direct integration is allowed only for unprotected task and feature branches.
- [ADR-0002](ADR-0002-direct-dev-governance-updates.md) — Azeez authorizes narrowly scoped Git-workflow and agent-instruction updates directly to `dev`, subject to file allowlisting, warning, synchronization, and non-forced-push checks.
- [ADR-0003](ADR-0003-maintain-one-line-adr-index.md) — Every ADR must have a one-line entry in the ADR index, which agents scan for relevance before reading applicable decisions in full.
- [ADR-0004](ADR-0004-event-driven-alerts-mvp-charter.md) - Feature 4 is Event-Driven Client Alerts, owned by Azeez and Hayyun with approved MVP scope, data boundaries, guardrails, retention, and budget defaults.
- [ADR-0004](ADR-0004-auditor-kafka-to-sqs-migration.md) — Auditor service messaging migrates from Kafka to Amazon SQS (standard queue plus DLQ), superseding the "no message broker" note in `docs/architecture/nfr-notes.md`.
- [ADR-0005](ADR-0005-cognito-security-across-features-1-and-2.md) — Features 1 and 2 share Cognito identity, with service-side JWT validation and Agent-owned client/account authorization (decision 4 partly superseded by ADR-0059: admins only read client data).
- [ADR-0006](ADR-0006-transaction-account-linkage-and-access.md) — Feature 3 links imports to CRM account UUIDs and serves authenticated transaction reads through User-service, with account ownership checked by client-profile (decisions 1–2 superseded by ADR-0037: transactions have their own database and are linked through account-service; decision 4 superseded by ADR-0035: ownership is now checked by account-service; decisions 3 and 5 superseded by ADR-0064: transaction-service checks its own callers and is called directly).
- [ADR-0017](ADR-0017-microservices-per-business-area.md) — One microservice and database per business area (accounts split from clients), with Go allowed for the auditor, client-service and account-service.
- [ADR-0020](ADR-0020-audit-write-path-outbox-shared-sqs.md) — Extends ADR-0004: services with a database write each audit event to their own outbox in the business transaction (existing request-middleware producers may save it right after the request, because of the cost of changing them), and a relay sends it to the shared `audit-insert` queue; transaction ingest writes its event in the import's transaction; Cognito triggers fail open.
- [ADR-0035](ADR-0035-account-ownership-across-services.md) — account-service copies each account's owning agent from client-service at creation using the caller's token, checks ownership locally, and client-service refuses to delete a client with accounts; both checks fail closed; supersedes ADR-0006 decision 4 (decision 4 partly superseded by ADR-0036: only undeleted accounts block a client's deletion); its never-changing-owner condition superseded by ADR-0060: reassignment updates the copy).
- [ADR-0036](ADR-0036-soft-deletion-of-clients-and-accounts.md) — Deleting a client or account sets `deleted_at` and keeps the row; deleted records are hidden from everyone and are not the same as `closed` accounts; uniqueness ignores deleted rows; deleting is not erasure; supersedes ADR-0035 decision 4 in part.
- [ADR-0037](ADR-0037-transactions-database-and-account-linking.md) — Transactions get their own database; the import links rows to accounts through account-service's `/internal/accounts/lookup`, authenticating with a Cognito client-credentials token, and fails closed; supersedes ADR-0006 decisions 1–2.
- [ADR-0033](ADR-0033-xf2-dashboard-topology-cache-audit.md) — X-factor 2: stateless dashboard-service fanning out with the caller's JWT, a 3-minute per-caller cache, and best-effort audit events.
- [ADR-0038](ADR-0038-dashboard-metric-definitions.md) — X-factor 2: what each dashboard figure means; only figures the data supports exactly, no sums across currencies, deleted records never counted, no composite agent score (account refusal and single-currency premise to be superseded by ADR-0062 on acceptance: account figures per currency, never refused).
- [ADR-0030](ADR-0030-client-data-envelope-encryption.md) — client-service encrypts the 11 personal client fields with per-client data keys kept in DynamoDB and wrapped by KMS, so deleting a key erases the client; email and phone stay unique through blind indexes keyed by one shared KMS HMAC key over normalised values.
- [ADR-0021](ADR-0021-audit-read-path-grpc-service-connect.md) — The auditor is internal-only and checks every caller's token; one changes-only activity feed in user-service (`GET /api/activities`) shows admins all agents' activities and agents their own, read over gRPC through ECS Service Connect; tamper findings are left to ADR-0022.
- [ADR-0022](ADR-0022-audit-tamper-resistance-and-crypto-shredding.md) — A hash chain over every field of each audit row and its parent's hash; an auditor database role that can only insert and read; a daily run-once chain-verify task that records each problem once in a findings table and anchors the head in S3 Object Lock; crypto-shredding for erasure.
- [ADR-0040](ADR-0040-cognito-triggers-java-lambda.md) — The Cognito login and password-reset triggers are one plain Java 25 Lambda at 1,769 MB (no SnapStart; measured cold start about 0.5 s), sending `COGNITO_TRIGGERS` events within a 3-second budget, never failing the sign-in, and logging failed sends for a replay tool.
- [ADR-0025](ADR-0025-identity-cognito-mfa-pkce-service-tokens.md) — Extends ADR-0005: mandatory MFA, managed login with PKCE (S256) from a public app client, client-credentials service tokens, Cognito triggers for login auditing, and sign-outs reported by the frontend to user-service (audit call first) for logout auditing.
- [ADR-0041](ADR-0041-client-identity-documents-and-manual-verification.md) — Identity documents (JPEG, PNG or PDF, up to 5 MB) are uploaded through client-service, encrypted with the client's data key and stored in a private SSE-KMS bucket; uploading never verifies; documents are optional for Verify, which records who verified, when and which documents, and records and shows a verification without one as such; no request is sent to the client (decision 1 partly superseded by ADR-0059: only agents upload and verify).
- [ADR-0024](ADR-0024-transaction-ingestion-sftp-lambda.md) — Import transactions from a self-hosted external SFTP server with a scheduled VPC-attached Lambda written in Go (extending ADR-0017's exception), JSON files, a ready-file protocol, idempotent inserts, rejected unsupported and unparseable files, and retries with a circuit breaker on the connection.
- [ADR-0034](ADR-0034-xf3-health-monitor-rules-and-bedrock-boundary.md) — Client Health uses deterministic versioned rules in one daily Java 25 ECS task, Bedrock Singapore for validated wording only with template fallback, a dedicated health database, scoped service calls, atomic audit outbox and ownership-scoped task access (Bedrock region partly superseded by ADR-0067: Nova Lite through its Asia-Pacific profile, same data rule).
- [ADR-0044](ADR-0044-client-health-transaction-intake-and-replay.md) — Client Health pulls bounded matched activity and six-month replay from a service-authenticated transaction API, with stable synthetic source fingerprints and fail-closed complete runs.
- [ADR-0046](ADR-0046-human-deploy-access-mfa-role.md) — Operators deploy as the hand-made role `crm-infra-admin` (administrator, MFA required, 4-hour sessions), assumed from IAM users in `crm-deployers` whose keys can reach nothing else; Identity Center is impossible in this member account, and Terraform cannot hold a role that its teardowns would destroy.
- [ADR-0048](ADR-0048-alert-worker-terraform-stack.md) — The alert worker is a scheduled ECS task in its own `stacks/alert-worker`, which reads the CRM stack's `alerts_worker_inputs` output, runs every four hours only while the stack is running and ingestion is on, and alarms on a non-zero exit; its AgentCore-specific decisions are superseded by ADR-0050.
- [ADR-0050](ADR-0050-event-search-provider-after-scp-block.md) — Use Tavily directly from the worker with restrictive domains/dates/result bounds and a Secrets Manager key because the Tokyo AgentCore Gateway and native Bedrock Web Search are blocked by an organization SCP; amends ADR-0009 and ADR-0048.
- [ADR-0066](ADR-0066-crm-linked-current-alert-holdings.md) — Approved CRM-linked current holdings and current-agent authorization for grouped event briefings, complete-account exposure, immutable snapshots and no fixture fallback; implemented locally, awaiting reviews and merge.
- [ADR-0051](ADR-0051-client-health-explicit-activity-classification.md) — Client Health requires an explicit CustomerInitiated/Automated/Unknown transaction classification so activity baselines exclude non-customer activity without inspecting descriptions.
- [ADR-0052](ADR-0052-client-health-versioned-signal-rules.md) — Client Health ruleset v1 deterministically detects recurring-credit interruption, 50%+ customer-activity decline, and two-period material net outflow with versioned thresholds and no pseudo-confidence score.
- [ADR-0053](ADR-0053-client-health-run-orchestration-and-task-admission.md) — Client Health SF04 owns deterministic leased analysis and success-only watermarks, while SF05 atomically owns active-task admission, 30-day severity-worsening cooldown and a 20-new-task daily Agent cap.
- [ADR-0051](ADR-0051-engagement-service-and-mail-dispatcher.md) — Agent engagement runs in a new Java 25 `engagement-service` with its own `db.t4g.micro` database and stack; a dispatcher in every task claims queued mail with `FOR UPDATE SKIP LOCKED` and a lease, so two tasks never claim the same row, delivery is at least once, and nothing is sent while the stack is stopped (extends ADR-0017 and ADR-0023).
- [ADR-0052](ADR-0052-calendar-invites-by-email.md) — Agents' calendars get CRM meetings through emailed iCalendar invites (`METHOD:REQUEST` and `CANCEL`, stable `UID`, rising `SEQUENCE`), one-way, with the agent as the only attendee and no OAuth or provider APIs.
- [ADR-0053](ADR-0053-email-delivery-through-ses.md) — All engagement email goes through SES from `mail.<legal_entity>.<domain>` with DKIM, MAIL FROM and DMARC, kept in a long-lived `stacks/mail-identity`; agents' addresses come from Cognito `ListUsers` by `sub`, clients' from client-service at send time and are never stored; sandbox recipients only for the demo (decisions 1, 3 and 9 partly superseded by ADR-0055: without the domain's hosted zone, mail comes from one verified address).
- [ADR-0054](ADR-0054-ai-follow-up-drafts-and-holiday-data.md) — Follow-up drafts come from Amazon Nova Micro, called through Bedrock Runtime in Singapore with its Asia-Pacific cross-region profile (never a global one), using placeholders and public holiday data only, pass a strict safety screen or fall back to a template, sit behind a kill switch and caps, and are sent only by the agent; holidays come from a versioned table seeded by migrations (decision 6 partly superseded by ADR-0056: agents edit plain text; decision 8 partly superseded by ADR-0057: new Singapore years synced from data.gov.sg; decision 3's model partly superseded by ADR-0067: Nova Lite, on in prod).
- [ADR-0055](ADR-0055-sender-address-without-a-domain.md) — In an account without the domain's hosted zone, engagement mail comes from one verified SES address, `sender_address`, set in both `stacks/mail-identity` and `stacks/agent-engagement`, with no DNS records and no DKIM alignment; with a domain, ADR-0053 is unchanged (supersedes ADR-0053 decisions 1, 3 and 9 in part).
- [ADR-0056](ADR-0056-drafts-edited-as-plain-text.md) — Agents edit follow-up drafts as plain text: the service fills in the client's first name and the agent's name when returning a draft, and marks each whole-word occurrence as its placeholder again when saving, so drafts are still stored without names; saving needs client-service and Cognito (supersedes ADR-0054 decision 6 in part).
- [ADR-0057](ADR-0057-holiday-sync-from-data-gov-sg.md) — engagement-service adds newly published Singapore public holidays from MOM's consolidated data.gov.sg dataset at start-up and daily, adding rows only, checking every name, and alarming on a missing next year or a mismatch; the calendar offers no month after the last covered year (supersedes ADR-0054 decision 8 in part).
- [ADR-0059](ADR-0059-admins-read-only-on-client-data.md) — Admins read every client, document and account but change none: a `RequireAgent` route check in client-service and account-service refuses admins with 403 on every client and account write, and the client page shows admins no write control; client reassignment (open item 24) is left as the one future admin write (supersedes ADR-0005 decision 4 and ADR-0041 decision 1 in part, and ADR-0050 decision 7).
- [ADR-0060](ADR-0060-client-reassignment.md) — Admins reassign clients: `clients.created_by_agent_id` becomes `assigned_agent_id` in `V1`; `POST /api/clients/reassignments` moves all of a user's clients, or chosen ones, to an enabled agent checked in user-service; client-service moves their accounts through account-service's `PUT /ownership/accounts` while holding the clients locked, so nothing moves if either fails; one audit event per client with the agent before and after; engagement data stays with the old agent (supersedes ADR-0035's never-changing-owner condition).
- [ADR-0064](ADR-0064-transaction-service-authenticates-its-own-reads.md) — transaction-service checks every caller's Cognito token and asks account-service about ownership with it; the ALB and dashboard-service call it directly and user-service's transaction routes are removed; it audits `/api` reads as `TRANSACTION_SERVICE` `READ` events through its own `read_audit_outbox`; serves HTTPS in production; the code stays in `services/sftp/receiver` (supersedes ADR-0006 decisions 3 and 5, ADR-0039 decisions 4–5 and ADR-0043's transaction-list routing and auditing).
- [ADR-0067](ADR-0067-nova-lite-asia-pacific-for-client-derived-wording.md) — Client Health explanations and follow-up drafts both use Amazon Nova Lite through `apac.amazon.nova-lite-v1:0` from Singapore (never a global profile; third-party models are blocked by Marketplace); Client Health asks for its JSON through a forced tool, only its analysis task may invoke the model, and both kill switches are on in prod; partly supersedes ADR-0034 (region) and ADR-0054 (decision 3's model).
- [ADR-0065](ADR-0065-client-health-matched-transaction-history.md) — Private Client Health transaction history route; scoped Cognito client-credentials authentication, all-client `[from,to)` reads, global keyset pagination, matched-only fields, validated source fingerprints, and synthetic signal/control cases.
- [ADR-0068](ADR-0068-follow-ups-from-client-health-and-alerts-and-draft-retention.md) — Follow-up drafts from a Client Health task (`HEALTH_CHECK_IN`) or an alert (`ALERT_FOLLOW_UP`), each checked through its owning service with the agent's token, with generic AI input and an `{{agent_details}}` slot the agent must fill in before sending; the agent is responsible for what they add, and sends are audited with `edited`; a draft's text is cleared when it is sent or discarded, open drafts expire after 14 days, and the agent gets a Bcc copy (partly supersedes ADR-0054 decisions 2, 4 and 6). Accepted by its owner for engagement-service; awaiting the Client Health and alerts owners' acknowledgement of the links.
- [ADR-0069](ADR-0069-frontend-security-headers-and-self-hosted-fonts.md) — Accepted 2026-11-02 after the ZAP scan: our own CloudFront response-headers policies replace the managed one, adding a Content-Security-Policy (app origin and Cognito only), Permissions-Policy, cross-origin opener and resource policies and removing `Server`, with a deny-all CSP on `/api/*`; no COEP; Inter and Material Symbols are bundled instead of loaded from Google Fonts. Owner: Neo Jia Wen.
- [ADR-0070](ADR-0070-api-throttle-sized-for-100-concurrent-agents.md) — Accepted 2026-11-02 after the full-scale load test: API Gateway's stage throttle becomes `api_throttle_rate_limit` and `api_throttle_burst_limit`, defaulting to 200 per second and a burst of 400, twice the Q&A's 100 requests per second for 100 concurrent agents. Owner: Neo Jia Wen.
- [ADR-0071](ADR-0071-test-only-in-vpc-zap-scanner.md) — Accepted 2026-11-02: `enable_test_tooling` (off by default) adds a one-off ZAP task in the app subnets whose own security group may reach the internal ALB, so the services can be scanned directly, and a self-emptying bucket for scan inputs, reports and the transaction seed file. Owner: Neo Jia Wen.

- [ADR-0032](ADR-0032-xf1-instrument-master-deterministic-matching.md) — X-factor 1: deterministic instrument master and matching with no vector similarity; search only instruments held by ≥ 2 clients and ≥ 20% of clients, or ≥ 50% of one account's value (ADR-0016).

- [ADR-0045](ADR-0045-producer-account-list-synced-from-crm.md) — The simulated bank's producer reads its account list from a file on the SFTP server on every run and publishes nothing when it is empty; `scripts/sync-producer-accounts.sh` copies the CRM's open, non-deleted accounts into it, each with its currency, through SSM Run Command, so the producer never calls the CRM and each transaction is in its account's currency (extends ADR-0024 decision 1).
- [ADR-0047](ADR-0047-business-dashboard-terraform-stack.md) — dashboard-service moves from `stacks/crm` into its own `stacks/business-dashboard`, which reads the CRM stack's `dashboard_inputs` output through `terraform_remote_state`, owns its image repository, security group and rules on the CRM's service groups, and is allowed on the audit queue through `extra_audit_producer_role_arns` (amends ADR-0042 decision 1).
- [ADR-0049](ADR-0049-alert-source-to-alert-pipeline.md) — After each worker run a pipeline matches stored sources to instruments deterministically, classifies each once, and creates alerts per agent who holds the instrument; the minimum excerpt is stored (ADR-0011), the search client is an IAM-signed MCP call, an operator replay is a one-off task with an audit event, and worker metrics export to CloudWatch on exit. (routing to the current agent amended by ADR-0066)
- [ADR-0051](ADR-0051-single-issuer-search-and-relevance-gate.md) — Replace 8-issuer grouped searches with four rotating single-issuer searches and reject results that lack an approved issuer name and actionable-event phrase; 2026-10-30 requester addendum configures commercial candidates with source citations while publisher rights remain unverified. Each issuer now gets two focused queries, results and corporate actions, within the same four-search ceiling.
- [ADR-0050](ADR-0050-accounts-pending-until-client-verified.md) — An unverified client's new accounts open as Pending (account-service reads `verification_status` from the client lookup it already makes and refuses other statuses with 403); after verifying, the agent may make them Active, and `PATCH /api/accounts/{id}` lets the owning agent change a verified client's account to any status, audited with its before and after values; admins do not manage client accounts (supersedes ADR-0035 decision 2 in part on acceptance; decision 7 superseded by ADR-0059).
- [ADR-0058](ADR-0058-every-deployment-ends-with-full-teardown.md) — Every deployment starts from an empty account and ends by destroying every Terraform stack, `mail-identity` and `bootstrap` included; stopping is only a pause within a deployment; one deployment at a time; budget alerts are made by hand outside Terraform: USD 200 at 10, 20, 40, 60, 80 and 100%, and USD 25 a month for Bedrock (supersedes ADR-0053 decision 2, ADR-0042 decision 1 and ADR-0029 in part).
- [ADR-0061](ADR-0061-imported-transactions-in-their-accounts-currency.md) — account-service's account lookup also returns each account's currency, and the import rejects, and audits, a row on a CRM account that has no currency or another one; a lookup answer without a currency is a lookup failure, so the file waits (supersedes ADR-0037 decisions 2 and 4 in part on acceptance).
- [ADR-0062](ADR-0062-dashboard-account-figures-per-currency.md) — Dashboard account figures per currency: account-service never refuses over currency, sums booked initial deposits per currency (in total and per agent) and leaves each day's value out when the window spans currencies; the per-agent table ranks deposits in a named currency (default SGD); `mixed_currencies` is removed; account creation is not limited to SGD (supersedes ADR-0038's account-service refusal and single-currency premise in part on acceptance).
- [ADR-0063](ADR-0063-openapi-contract-tests.md) — Every REST route has an OpenAPI 3.0.3 contract in `docs/api` (users, clients, accounts, transactions and corrupted logs written from the code); Java tests check every MockMvc response and Go controller tests every handler response against them, route tests fail on any undocumented route, consumers check canned replies against the provider's contract, and CI validates the specs and runs `oasdiff breaking` on pull requests, with deliberate breaking changes accepted in writing in `docs/api/accepted-breaking-changes.txt`.

## Maintenance rule

Add or update exactly one concise entry whenever an ADR is added, superseded, or
has its status changed. Keep historical entries and identify the superseding ADR
rather than deleting an old decision from this index.
