## Goal

Import external SFTP transactions, link matched records to CRM account UUIDs, and provide an authenticated API for Admins and Agents to view transactions within their account access scope.

## Scope

- Use the shared CRM PostgreSQL database for client, account, and transaction data.
- Store a resolved `account_id` foreign key for each transaction whose source `account_id` matches a CRM account UUID. Keep unmatched source references for reconciliation, with a null CRM account link.
- Serve the public transaction read routes from transaction-service (the receiver's read API), which authenticates the Cognito access token and enforces the Admin/Agent role ([ADR-0064](../adr/ADR-0064-transaction-service-authenticates-its-own-reads.md), replacing user-service in front of the receiver).
- Delegate account ownership verification to account-service's authenticated account endpoint, called with the caller's token. Agents can read their own accounts; Admins can read any account.
- The receiver repository uses SQLBoiler to return rows linked to the requested account.
- Keep the Client Health Monitor's transaction-history read separate from the user-facing routes: a private receiver route authenticated with Cognito client credentials and `crm-transactions/read` returns all matched rows over `[from,to)`, with global keyset pagination.
- Store `activity_kind` (`CustomerInitiated`, `Automated`, or `Unknown`) and nullable `source_fingerprint` on imported records. Synthetic replay uses stable IDs/fingerprints and covers at least six complete calendar months.

## Acceptance criteria

- Imported records matching an existing CRM account UUID have `transactions.account_id` set and reference `accounts.id`.
- Unmatched source references remain unlinked and are not returned by account transaction reads.
- `GET /api/accounts/{accountId}/transactions` on transaction-service requires a valid Cognito access token and an `ADMIN` or `AGENT` group.
- The request passes only after account-service confirms the account is accessible to that caller.
- Admins can request any account; Agents cannot retrieve transactions for accounts owned by another Agent.
- transaction-service audits each `/api` read, refused ones included, through its own `read_audit_outbox`.
- The Client Health route requires the allow-listed Cognito service client and `crm-transactions/read`; it returns matched rows across clients with non-null CRM client/account IDs and omits descriptions, source account references, and import metadata.
- Synthetic history generation is repeatable for the same CRM account IDs and provides six complete calendar months with recurring-credit interruption, activity-decline, sustained-net-outflow, and healthy-control cases.
- Feature plan, schema migration, API behavior, local run instructions, and audit behavior remain documented.
