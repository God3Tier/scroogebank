A2. Audit hash chain (ADR-0022, Accepted 2026-10-12)
    (ADR-0022 amended and accepted in PR #86, including the anchor and
    ANCHOR_MISMATCH. a-f DONE: merged to dev in PR #87, 2026-10-13.
    g DONE: merged to dev in PR #88. Left: the anchor bucket, task, schedule,
    logins and alarms, which wait for infrastructure (see the auditor README).)
    Code owner: the auditor's owner (Hayyun). The spec requires
    tamper-resistant audit logs, and the current chain is not.
    Also fixed: the payload was hashed as received but stored as jsonb, so
    nearly every row would have failed verification; the writer's
    SELECT ... FOR UPDATE needed UPDATE privilege (now an advisory lock).
    a. The hash leaves out parent_hash and event_id
       (services/auditor/src/internal/repository/audit/store_audit_chain.go:57).
       Someone with database access can edit a row, recompute its hash and
       update the next row's parent_hash; the next row's own hash does not
       change, so verification passes. Hash every field, including event_id
       and parent_hash, with an unambiguous encoding (fields are joined with
       no separator today).
    b. Verification skips the newest row and never compares a row's
       recomputed hash with its own stored hash
       (src/internal/service/audit/verify_chain.go:30). Check every row.
    c. audit_log.timestamp is TIMESTAMP, not TIMESTAMPTZ in UTC
       (data/schema.sql).
    d. chain-verify cannot be built: src/cronjob/main.go is `package cronjob`,
       not `package main`, and the Dockerfile builds only src/serverd. It
       also runs internal timers (@every 24h, @every 1h). Make it a binary in
       the auditor image that runs once and exits, for EventBridge.
    e. On a mismatch it deletes the row and re-links the chain
       (src/internal/repository/audit/remove_audit_log.go). Record a finding
       instead and leave the chain as it is. Which operations admins have on
       findings is open item 13 (C2); it need not block a-d.
    f. Give the auditor a database role with only INSERT and SELECT on
       audit_log.
    g. Write the chain head to an S3 Object Lock bucket (needs infra;
       LocalStack locally). Done: each run checks the newest anchor and
       writes a new one, locked in governance mode for 7 days.
    Changing the hash format invalidates existing chains. Nothing is
    deployed, so only local databases need recreating (make db-reset).
    Still open from ADR-0022: decision 5 (encrypted audit payloads for
    erasure) waits on open items 11 and 21 (C4).

    files carry a control record (record count and amount total) to catch

    global.openai.gpt-5.6-luna through Bedrock in us-east-1
    (src/main/resources/application.yml:66-75); ADR-0031 proposes Bedrock
    in Singapore. The model sees public data only, so this is a choice about
    residency and cost. Owners: Azeez, Hayyun.
